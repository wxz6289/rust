# Rust 生命周期（Lifetimes）详解

本文档系统化说明 Rust 中的生命周期（lifetimes）概念、规则、常见模式与常见错误，便于放入项目文档作参考。

## 概念与动机

- 生命周期描述引用（reference）有效的作用域区间，编译器通过生命周期检查防止悬垂引用（dangling reference）。
- 生命周期注解只影响借用检查（编译期），不改变所有权或运行时行为。

## 基本术语

- `'a`, `'b`：显式生命周期参数（命名惯例以单引号开头）。
- `'static`：静态生命周期，数据在整个程序运行期都有效（例如字符串字面量）。

## 什么时候需要生命周期注解

- 当函数返回一个引用，且返回的引用依赖于输入参数时，通常需要为参数和返回值标注生命周期。

示例：返回两个字符串中更长的那个引用

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
	if x.len() >= y.len() { x } else { y }
}
```

- 结构体包含引用字段时，结构体类型需要生命周期参数：

```rust
struct Ex<'a> { part: &'a str }
```

## 生命周期省略规则

编译器在常见简单场景会自动推断生命周期，遵循三条省略规则：

1. 每个输入参数都有自己的生命周期参数（如有 N 个输入参数则有 N 个生命周期）。
2. 如果只有一个输入生命周期，那么该生命周期被赋给所有输出生命周期。
3. 如果方法有 `&self` 或 `&mut self`，输出生命周期被赋为 `self` 的生命周期。

这使得许多函数签名（例如 `fn first_word(s: &str) -> &str`）在实际代码中不需要显式注解。

## 常见代码模式与解释

1) 省略规则可以工作（无需注解）

```rust
fn first_word(s: &str) -> &str { /* ... */ }
```

2) 必须显式标注的情况：当返回引用来自于特定参数时

```rust
fn choose<'a>(x: &'a str, _y: &str) -> &'a str { x }
```

3) 错误示例：返回指向局部变量的引用（悬垂引用）

```rust
let r;
{
	let s = String::from("hello");
	r = &s; // 编译错误：s 作用域结束后 r 会悬垂
}
```

## 结构体与生命周期

- 结构体中包含引用时必须为结构体定义生命周期参数：

```rust
struct Holder<'a> { val: &'a str }

impl<'a> Holder<'a> {
	fn val(&self) -> &str { self.val } // elision：返回生命周期同 &self
}
```

- 如果结构体拥有所有权（例如 `String`），就不需要生命周期参数。

## 方法、impl 与生命周期省略配合

在 `impl<'a> Holder<'a>` 中的方法通常能借助省略规则，方法返回 `&str` 时编译器会推断为与 `&self` 相同的生命周期。

```rust
impl<'a> Holder<'a> {
	fn get(&self) -> &str { self.val }
}
```

## `'static` 生命周期

- 字面量字符串具有 `'static` 生命周期：`let s: &'static str = "hello";`
- 需要将数据跨线程传递或放入全局缓存时，常常需要 `'static` 或使用拥有所有权的替代方案（`String`, `Arc<String>`）。

## 生命周期子类型与包含关系（直觉）

- 生命周期存在包含关系，例如 `'long` 包含 `'short`（`'long: 'short`），具有更长生命周期的引用通常可以用于期望较短生命周期的位置。编译器会比较作用域来决定是否满足约束。

## 高级话题简述

- 高阶生命周期（Higher-Ranked Trait Bounds，HRTB）：像 `for<'a> Fn(&'a T)` 的写法用于描述“对任意生命周期都成立”的 trait 约束，常用于库设计或高阶函数。

示例（简略）：

```rust
fn call_for_any<F>(f: F) where for<'a> F: Fn(&'a i32) { /* ... */ }
```

## 常见错误与解决策略

1. 返回引用指向局部变量（悬垂引用）
   - 解决：返回拥有所有权的值（`String`）或使数据的所有者活得更久（提升作用域）

2. 编译器无法推断生命周期需显式注解
   - 解决：为函数参数和返回值添加生命周期注解，或改为传递所有权

3. 多个借用冲突（可变与不可变借用混用）
   - 解决：缩小借用作用域、使用克隆或重构数据结构以减少共享可变性

4. `'static` 要求不满足（例如线程或全局缓存）
   - 解决：使用 `Arc<T>`、`Box<T>`、或传入 `String` 而非 `&str`

## 实践建议

- 初学时优先使用拥有所有权（如返回 `String`）来避免复杂生命周期注解；在性能关键路径或 API 设计需要时再使用引用与显式生命周期。
- 在公开 API 中，尽量让生命周期关系清晰可读，必要时在文档注释里说明引用来源与有效期。
- 遇到借用报错时，把问题缩小为最小可复现示例，并根据编译器提示调整注解或数据所有权。

## 示例合集（速查）

- 返回最长字符串引用：

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
	if x.len() >= y.len() { x } else { y }
}
```

- 结构体包含引用：

```rust
struct Ex<'a> { part: &'a str }
impl<'a> Ex<'a> { fn part(&self) -> &str { self.part } }
```

- 将局部数据改为拥有值返回：

```rust
fn make_owned() -> String { String::from("owned") }
```
